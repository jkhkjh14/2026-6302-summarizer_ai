## 1. Постановка задачи

В современном информационном обществе объём текстовых данных растёт экспоненциально. Пользователи ежедневно сталкиваются с необходимостью быстро ознакомиться с большим количеством материалов: новостные статьи, научные публикации, отчёты, юридические документы и др. Ручное сокращение таких текстов требует значительных временных затрат и субъективно.

**Цель работы** – разработать веб-приложение (ИИ-агента) для автоматической суммаризации текстов из различных источников с возможностью управления степенью сжатия.

**Конкретные задачи:**
- Реализовать извлечение текста из четырёх типов входных данных: ручной ввод, веб-URL, файлы (TXT, PDF, DOCX) и изображения (JPG, PNG) с использованием OCR.
- Интегрировать генеративную модель YandexGPT для смыслового сжатия текста.
- Обеспечить гибкое управление длиной итогового пересказа (три предустановленных уровня + пользовательское значение).
- Предоставить возможность скачивания результата в форматах TXT и DOCX.
- Подсчитывать метрики: количество слов в оригинале и пересказе, процент сжатия.
- Спроектировать удобный веб-интерфейс с минимальным порогом входа.

## 2. Используемый подход

### 2.1. Выбор модели суммаризации

В качестве ядра суммаризации использована **YandexGPT** – облачная генеративная модель, предоставляемая Яндекс.Облаком (используется версия с увеличенным лимитом токенов для более точного соблюдения объёма).
Выбор обусловлен:
- Высоким качеством генерации на русском языке;
- Поддержкой настройки параметров генерации (температура, максимальное число токенов);
- Доступностью через REST API, что упрощает интеграцию;
- Наличием бесплатного тарифа для образовательных целей.

Для управления степенью сжатия применяется **процентный подход**: пользователь задаёт долю слов от исходного текста, которую хочет сохранить. На основе этого вычисляется целевое число слов (`desired_words`), которое передаётся в системный промпт модели. Для повышения точности реализован механизм повторных запросов: если первый ответ оказывается короче 80% от желаемого, система отправляет второй запрос с более строгой инструкцией, что значительно улучшает соответствие заданному проценту.

### 2.2. Извлечение текста из различных источников

Для обеспечения универсальности разработаны отдельные модули:

- **Веб-страницы:** используется комбинация библиотек `newspaper3k` (быстрое извлечение основного контента) и `BeautifulSoup4` с `requests` для резервного парсинга. Обработка включает удаление HTML-тегов, скриптов и стилей.
- **PDF-документы:** библиотека `PyPDF2` извлекает текст со всех страниц, объединяя их в единую строку.
- **DOCX-документы:** библиотека `python-docx` читает абзацы документа, сохраняя их последовательность.
- **Изображения:** используется `EasyOCR` – глубокое нейросетевое решение для распознавания текста. Для снижения нагрузки на память изображения предварительно сжимаются до разрешения 1920×1080 с сохранением качества 85% (формат JPEG).

### 2.3. Серверная инфраструктура

Приложение построено на **Flask** – лёгком фреймворке для Python. Выбор обусловлен:
- Простотой разработки и отладки;
- Встроенным веб-сервером для тестирования;
- Широкой экосистемой расширений.

Взаимодействие с фронтендом реализовано через REST-маршруты:
- `/` – отдача главной страницы;
- `/summarize_text` – обработка текста (JSON);
- `/summarize_url` – обработка URL (JSON);
- `/summarize_file` – загрузка файла (multipart/form-data);
- `/download_txt` и `/download_docx` – генерация и отдача файлов.

## 3. Архитектура решения

### 3.1. Общая структура

Система построена по классической **клиент-серверной модели** с разделением на три логических уровня:

1. **Представление (Frontend)** – одностраничное приложение на HTML5 с использованием Bootstrap 5 для адаптивной вёрстки. Коммуникация с сервером осуществляется через асинхронные запросы (Fetch API).
2. **Бизнес-логика (Backend)** – Flask-приложение, которое координирует все операции: приём данных, выбор модуля извлечения, вызов суммаризации, подсчёт метрик, формирование ответа.
3. **Внешние сервисы** – YandexGPT API (суммаризация) и EasyOCR (распознавание изображений).

### 3.2. Модули и их взаимодействие

Подробная схема работы (текстовое описание):

1. **Пользователь** выбирает тип ввода (текст, URL, файл) и желаемую степень сжатия.
2. **Flask-маршрут** принимает запрос, извлекает данные и определяет способ получения текста.
3. **Модуль извлечения**:
   - Для текста – возвращает переданную строку.
   - Для URL – парсит страницу с помощью `newspaper3k`, при неудаче – `BeautifulSoup` + `requests`.
   - Для файла – определяет расширение и вызывает соответствующий парсер (PyPDF2, python-docx, или EasyOCR).
4. **Модуль суммаризации**:
   - Проверяет длину текста (если < 50 символов, возвращает его без изменений).
   - Обрезает входной текст до 15 000 символов (во избежание ошибок API).
   - Формирует системный промпт с указанием точного числа слов (`desired_words`) и стиля, зависящего от выбранного процента (краткий, сжатый или подробный).
   - Отправляет запрос к YandexGPT с параметрами: модель `yandexgpt`, температура 0.0, `maxTokens = desired_words * 1.2`.
   - Если количество слов в ответе меньше 80% от желаемого, отправляется повторный запрос с усиленной инструкцией «не останавливайся, пока не достигнешь указанного числа».
   - Полученный ответ возвращается без принудительного обрезания (обрезка применяется только при превышении 110% от желаемого).
5. **Модуль метрик**:
   - Точный подсчёт слов в оригинале и суммаризации с использованием регулярного выражения `\b\w+(?:-\w+)*\b`.
   - Вычисление процента сжатия.
6. **Модуль экспорта**:
   - Для TXT – формирует байтовый поток с кодировкой UTF-8.
   - Для DOCX – создаёт документ с заголовком и текстом, сохраняет в `BytesIO`.

### 3.3. Управление состоянием

Приложение не использует постоянное хранилище (базу данных) — все данные обрабатываются в оперативной памяти и не сохраняются. Это упрощает развёртывание и соответствует требованиям конфиденциальности: пользовательские тексты не сохраняются на сервере.

## 4. Результаты и их анализ

### 4.1. Функциональные возможности

Разработанный продукт демонстрирует:

- **Универсальность ввода:** поддерживает 4 типа источников, включая распознавание отсканированного текста.
- **Гибкость сжатия:** пользователь выбирает процент от исходного текста (от 10% до 90% с шагом 5%) — это позволяет адаптировать длину пересказа под любые тексты.
- **Прозрачность:** в результате показывается точное количество слов в оригинале и пересказе, а также степень сжатия в процентах.
- **Экспорт:** результат можно сохранить в открытом текстовом формате (TXT) или в редактируемом документе Microsoft Word (DOCX).

### 4.2. Экспериментальная оценка

Были проведены тесты на 20 разнородных текстах (научные статьи, новости, художественная литература, техническая документация) длиной от 200 до 5000 слов.

| Параметр | Результат |
|----------|-----------|
| Среднее время обработки (без учёта OCR) | 3–5 секунд |
| Качество суммаризации (субъективная оценка) | 4.2 из 5 (сохранение смысла) |
| Точность соблюдения заданного процента (после повторных запросов) | Отклонение от целевого числа слов в пределах 20–30% (вместо 60–70% без повторных запросов) |
| Процент сжатия при выборе «кратко» | 70–85% |
| Процент сжатия при выборе «подробно» | 40–60% |
| Успешность распознавания текста с изображений | 85% при чётких печатных текстах |

Благодаря введённому механизму повторных запросов удалось значительно повысить точность соблюдения заданного объёма: если при первом запросе отклонение могло достигать 60–70%, то после второго запроса оно снижается до 20–30%, что делает управление длиной пересказа более предсказуемым.

**Ключевые наблюдения:**
- Модель YandexGPT хорошо справляется с русскоязычными текстами, но может «пересказывать» слишком общо, теряя специфические термины.
- При ручном вводе желаемого числа слов модель часто выдаёт близкий по объёму ответ, но не всегда точно укладывается в заданное количество.
- OCR EasyOCR даёт сбои на изображениях с низким разрешением или сложным шрифтом, однако предварительное сжатие улучшает производительность и стабильность.

## 5. Ограничения и пути решения

### 5.1. Текущие ограничения

- **Длина входного текста:** при превышении 15 000 символов текст обрезается, что может привести к потере части информации.
- **Зависимость от внешнего API:** при отсутствии интернета или проблемах с Яндекс.Облаком сервис недоступен.
- **Тематическая модерация:** YandexGPT может блокировать запросы на политически чувствительные темы.
- **Точность OCR:** распознавание рукописного текста не поддерживается, для печатного требуется хорошее качество снимка.
- **Точность соблюдения объёма:** несмотря на механизм повторных запросов, абсолютная точность не гарантируется; отклонение в 20–30% считается приемлемым для генеративных моделей.

### 5.2. Возможные улучшения

- **Локальная модель суммаризации:** использование ruT5 или mT5 позволит работать офлайн и снизить задержки.
- **Поддержка других языков:** расширение набора языков для OCR и суммаризации.
- **Асинхронная обработка:** для больших файлов (PDF > 50 страниц) можно реализовать фоновую обработку с уведомлением.
- **Кэширование:** хранить результаты суммаризации для повторяющихся текстов в локальной базе (SQLite).
- **Улучшение OCR:** добавить предобработку изображений (бинаризация, повышение контраста) для повышения точности.
